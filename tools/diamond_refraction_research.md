# 钻石内部折射 · 研究与修复记录（feat/diamond-demo）

> 用户反馈：「钻石内部的折射是错的」 + 「按理来说钻石应该只有表面会进行反射，感觉这个钻石内部也在进行反射」
> 本文档 = ① 权威依据（含链接）② 现实现的逐项判决与偏差表 ③ 修法与验收。
> 复现脚本：`tools/diamond_refraction_audit.py`（数值审查 + 偏差表）、`tools/verify_diamond_geometry.py`（几何+静态约束，57×PASS）。

---

## 0. 结论（TL;DR）

1. **几何/光路主干是对的**：现实现的「入面 Snell → 内部 TIR 弹射 → 出射面再折射 → 背景平面求交 + 逆投影」这条链，
   与权威描述（Gemology Project 的 Fig.1 光路、piellardj 的 diamond-webgl）一致；凸多面体求交用的是
   Kay & Kajiya 半空间 slab 语义（入点 = 前向平面 t 的最大值，出点 = 后向平面 t 的最小值），也正确。
   数值复核：入面法线符号 ✓、内部反弹 = `reflect(dir,n)` ✓、自内向外的 TIR 判据 `sinθ > 1/n` ✓（θc = 24.42°）、
   色散每段界面共用一个 per-channel ior ✓、冠部进入的光 0 条直穿亭部（无「误当穿透」）✓。
2. **真正的错在【出射/回光的方向 → 背景采样】这一步**：真实明亮式切工的**主光路是从冠部折回、朝上出射**
   （gemology 原文：光被关在宝石里，最后**从冠部**折出）。而现实现对「朝上出射」的射线用的是
   `uCenter + (dx,−dy)·0.5·R` 这种**与场景几何无关的方向偏移**（`bgCoordSoft`），不是任何平面的逆投影。
   ⇒ 面朝上的默认姿态下，**61.5% 的出射像素走这条假分支**（+19% 弹射用尽也退到它），
   采样点中位偏差 **258px = 0.73 倍腰棱半径**，其中 **91.3% 的采样点落在钻石自身覆盖区内**，
   等于「对着宝石脚下那一小片最平滑的背景取色」⇒ 每块刻面拿到一块**平滑、无结构、位置还不对**的颜色
   ⇒ 观感就是「宝石内部自己在反射 / 里面像嵌了一层平色玻璃」。
3. **第二个偏差：内部界面没有按 Fresnel 分光（能量不守恒）**。内部非 TIR 界面现取 100% 透射、
   把反射支路整条丢弃 ⇒ 内部回光比物理值亮 `1/(1−R)` 倍（正入射 1.21×、掠射更大）。
   物理上：**只有表面那一次 Fresnel 反射是清晰镜像**；内部是 TIR 回来的**多次、更暗、错位**的光（brilliance），
   界面本身**不是**额外的可见镜面。修法按 (1−R_入)·Π(1−R_内) 对透射路径加权。
4. 修法（默认开启，一行可关）：`uEnvModel`（1 = 几何一致环境，0 = 旧假软投影回退）。

## 1. 依据 ①：明亮式切工的光路（进冠部 → 亭部全反射 → 从冠部折回）

| 结论 | 来源 | 对本实现的含义 |
|---|---|---|
| 光从**冠部**进入后被关在宝石里：**在亭部面上以大于临界角的角度入射 ⇒ 全反射（TIR）**，可能**连续两次**在亭部面上反射，最后在**冠部**以小于临界角的角度**折射出射** | Gemology Project〈Brilliance〉（Fig.1 的光路 1→2→3→4 逐点描述）：http://gemologyproject.com/wiki/index.php?title=Brilliance | 现实现的循环语义（TIR 记账、出射面必须使 `sinθ < 1/n`）方向正确；**默认 uBounces=2 太少**（真实路径常需 2 次亭部 TIR + 1 次出射，弹射预算 2 时 19% 像素退化） |
| 「**在切工良好的透明宝石里，所有从冠部进入的光都会被关在宝石里一段时间，然后从冠部折射出来**」 | 同上（原文：*In a well proportioned transparent stone, all light that enters the faceted stone through the crown will be trapped inside the stone for a while and then be refracted out of the stone through the crown.*） | ⇒ **朝上（朝观察者）出射是主路径**，必须几何正确，不能是"软投影"占位 |
| 亭部过浅 / 过深 ⇒ 光从**亭部漏出**（fish-eye / window / nailhead），宝石显得"发白/发水/发暗" | Gemology Project；aretediamond〈How Diamond Interacts with Light〉：https://aretediamond.com/diamond-encyclopedia/light-performance ；biogemlab（理想亭角 40.6–41.0°）：https://biogemlab.com/blog/cutting-proportions-memorial-diamonds-brilliance.html | 判据：从冠部进入的光**不得**从亭部穿出（本模型实测 0 条 ✓）。这也是"是否误当穿透"的硬指标 |
| 亮度/火彩 = brilliance（折回的白光）+ fire（色散）+ scintillation；看的是「**返回观察者的光**」 | aretediamond〈How Diamond Interacts with Light〉；piellardj〈Diamond — Explanations〉：https://piellardj.github.io/diamond-webgl/readme/ （*The goal is to reflect as much light as possible towards the viewer (that is, towards the top of the gem)*） | 渲染目标 = 把"朝上回光"这一支算对 |

## 2. 依据 ②：IOR 2.417 / 临界角 24.4° / Fresnel（含自内向外）

| 结论 | 来源 | 含义 |
|---|---|---|
| 金刚石 IOR = **2.417**（空气取 1），临界角 **θc = arcsin(1/n) ≈ 24°26′ ≈ 24.4°** | Gemology Project〈Brilliance〉（原文给出 `critical angle = arcsin(1/n) = arcsin(1/2.417) ≈ 24°26′`）；globalcalcs〈Critical Angle of Refraction〉：https://globalcalcs.com/en/science/critical-angle-refraction | 内部界面的 TIR 判据是 **`sinθ > 1/n`（从内部、从法线量起）**，与"从外部入射"完全不同；本实现等价使用 `k = 1−η²(1−cos²θ) < 0`，η = n（自内向外），数学等价 ✓ |
| TIR **只**发生在「光密 → 光疏」方向，且是**全反射**（能量 100% 留内部） | globalcalcs（*TIR is directional — denser → rarer only*） | 内部 TIR 事件不加 Fresnel 折扣（实现正确）；**非 TIR 的内部界面必须按 Fresnel 分光**（实现缺失，见 §5-C） |
| 色散：n 随波长变 ⇒ 蓝端 n 略大、θc 略小（金刚石 ~24.0°@蓝 vs ~24.6°@红），色散系数 0.044（686.7nm vs 430.8nm 的 n 差） | globalcalcs〈Critical Angle of Refraction〉；aretediamond〈How Diamond Interacts with Light〉 | ⇒ **每个通道要有自己的 ior，并在"每一段界面"用它**（不是只在出射段）；阈值（TIR 判据）也随之按通道判断 |
| Fresnel：能量在反射/透射间分配，θ 越大反射越强（掠射→1） | piellardj〈Diamond — Explanations〉（Fresnel 段 + `F = Fr + Ft`、`θc` 公式）；Graphics Gems Revisited（SIGGRAPH 2004, Guy & Soler）Eq.10：https://artis.inrialpes.fr/Publications/2004/GS04/GraphicsGemsRevisited.letter.pdf | 现实现只在**入面**做了 Schlick 近似（F0 = ((1−n)/(1+n))² = 0.172 @ 正入射，与精确未偏振值 0.1712 一致 ✓），内部界面**没做分配** ⇒ 见 §5-C |

**关键公式（论文/实现里的形式，本文档据此复核）**

* 凸多面体：入点 `t_in = max{ (d_i − n_i·o)/(n_i·dir) : n_i·dir < 0 }`；出点 `t_out = min{ …: n_i·dir > 0 }`；命中 ⇔ `t_in ≤ t_out` 且 `t_out > 0`。
* Snell 向量式（GLSL `refract` 同形）：`T = η·L + (η·cosθi − √(1−η²(1−cos²θi)))·N`，`η = n1/n2`，`N` 朝向入射侧；`k < 0` ⇒ 全反射。
* 反射：`R = L − 2(n·L)n`（与 n 的朝向无关）。
* 临界角：`sinθc = n2/n1`（n1 > n2）；金刚石 `sinθc = 1/2.417 ⇒ θc = 24.42°`。
* 未偏振 Fresnel：`Rs = ((n1cosθi − n2cosθt)/(n1cosθi + n2cosθt))²`，`Rp = ((n1cosθt − n2cosθi)/(n1cosθt + n2cosθi))²`，`R = (Rs+Rp)/2`（Schlick 近似 `R = F0 + (1−F0)(1−cosθ)^5`，`F0 = ((n1−n2)/(n1+n2))²`）。
* 逆投影（针孔相机 z=camZ、胶片 z=0）：世界点 P → 屏幕点 `P.xy · camZ/(camZ − P.z)`；背景平面 z=−uDepth ⇒ 缩放 `camZ/(camZ+uDepth)`。

## 8. 不确定项 / 已知局限（诚实清单）

1. **"内部回光"本身是物理正确的**，不是缺陷：真实明亮式切工的光就是"从冠部折回"（Gemology Project 原文），
   所以修好后宝石内部**仍然**能看到环境内容 —— 那正是 brilliance。判据不是"内部有没有内容"，而是
   ① 只有**表面**那一次 Fresnel 反射是**几何精确的清晰镜像**；② 内部回光按 `(1−R)` 能量加权（更暗、错位、多次）；
   ③ 环境采样位置必须来自场景几何（本次修的正是这一点，旧实现偏 325px / 0.92 半径且 100% 落在宝石脚下）。
2. **前半球（相机一侧）没有场景几何**：本 app 只有一张屏幕空间背景照片，因此朝上支路用的是
   "背景平面镜像 + 保向有界压缩"这一**模型选择**，不是严格解；几何上严格的只有朝下支路（背景平面求交 + 逆投影）。
   若要做到物理严格，需要一张环境贴图/cube map（piellardj、Graphics Gems Revisited 的做法）—— 属后续工作。
3. **低多边形感/马赛克感**：17 面简化切工 + 平面着色本身就会给出硬边刻面（真实宝石也是硬边刻面，
   但真实明亮式是 57–58 面）；4× 特写里仍有少量"掠射方向刻面内容被压扁"的痕迹（压缩映射的固有代价）。
4. **帧成本只证明了"无回归"**：模拟器显示器 60Hz 封顶，三种配置都顶在 59.9+ fps ⇒ 无法据此断言
   bounces=4 在 120Hz 真机上的绝对余量（需真机实测）。
5. **色散参数**：R/B 出射方向分离 中位 1.86°（色散 0.012）偏大 —— 这是模型里 `ior*(1±d)` 的直接结果，
   本轮的"色散施加段正确性"已核（每段界面共用同一 iorK），但**色散强度的绝对值**未与金刚石
   0.044 色散系数做定量标定（需要按波长取 n(λ) 才是严格做法）。
6. 状态栏时钟与底部面板排版在改前/改后两次抓图间有 ~2.3% 像素差（UI 噪声，非渲染差异）；
   同构建 A/B（env1 vs env0）体外 **0.0%** 才是有意义的证据。
7. 我为了 A/B 对比把 emulator-5554 的 `wm size` 从别的会话留下的 `920x1472` 覆盖重置为物理尺寸
   `1840x2944`（`wm size reset`）—— 若其它会话依赖那个覆盖需自行恢复。
